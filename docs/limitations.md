# V1 已知限制

- 上传最多 10 MiB，脱敏、解析和入库仍在同步请求内完成，但由线程池执行，不阻塞 Web 事件循环。原始 multipart 请求在解析前受限并留在内存。上传异步化需要独立的任务契约和恢复设计，尚未实施。
- Celery 使用 solo，不能靠 soft/hard time limit 配置获得可靠的任务中断。僵尸回收标记超时不等于终止已卡住的进程；需要人工重启 Worker。worker/beat 尚无独立的就绪探针，`Up` 不代表能消费任务。
- 阶段进度可持久化，但没有阶段级续跑。失败重试新建 Run，不复活终态。
- 旧 Run 没有 queued_at 时无法推断真实排队时长；不自动给它补造时间。
- 缺少项目、数据源、Run 的删除与改名入口。同格式上传可能复用来源；网页还不能为每份文件单独创建数据源。
- 上传去重发生在同一数据源内；没有跨数据源内容去重。列表有 API 游标，网页只显示最近 100 个 Run、50 个分组/事故、每组最近 100 个事件。
- IP 默认保留，网页可以勾选脱敏。规则不做通用人名、机构 NER；未知敏感字段仍可能漏检。JSON 数字计数器保留，手机号等敏感命名字段会脱敏。上传不允许 mask_disabled；no_mask_fields 仍只是记录项。
- 脱敏占位符使用 16 位哈希。历史文件中的 8 位占位符保持原状，与新版本不能直接按占位符等同关联。
- 原全局运行时知识没有可靠的项目归属，不自动迁移、不回退读取。文件锁和原子替换保护单次修改，staging 与 confirmed 之间不具有跨文件事务。
- Logout 清除浏览器 Cookie；没有 token 撤销表、改密和找回密码流程。
- 纯规则路径不调用模型。模型凭据/参数错误会明确失败并保留规则结果，网络错误可重试后以 partial_success 返回规则结果。未填写 `.env` Key 不保证禁用其他凭据来源，解析顺序见 README。
- 模型预算仍依赖正确的型号、价格配置；并发分析尚无预算额度预占。不要把已有三道检查点当成精确的并发资金预留系统。
- 不支持实时流、跨文件历史基线、自动处置、微服务或 Kubernetes。单机回环部署是当前支持范围。
